# Как провести и оценить сравнение

Из корня проекта в среде с установленным и уже авторизованным Codex:

```text
python tools/run_comparison.py eval-traffic --scenario traffic
python tools/run_comparison.py eval-complete --scenario all
```

Для нового прогона выберите новую папку. При сбое запустите ту же папку с флагом `--resume`; завершённые этапы пропускаются. `--arm agent` запускает только агента, `--scenario megafon` выбирает кейс оператора. Для проверки файлов без вызова модели добавьте `--prepare-only`. Скрипт использует существующий способ входа в Codex. При необходимости укажите один и тот же доступный идентификатор модели через `--model`. Если параметр пропущен, отчёт не утверждает, какая именно модель запускалась. Результаты включают время от старта процесса, наличие ответа и состояния, сообщения CLI и доступный счётчик токенов. Счётчик токенов не является ценой.

В обеих версиях один пользовательский запрос, те же входные данные, шаблоны и расчётные инструменты. Веб-поиск в этом сценарии исключён; для модели требуется работающая среда Codex. В целевой версии добавлены AGENTS.md и workflow.md. Базовая версия: тот же Codex без инструкций продукта, а не веб-интерфейс ChatGPT. Это сравнение проверяет влияние инструкции и процесса; оно не измеряет превосходство над всеми чатами. Веб-доступ в отдельной демонстрации допустим для открытых источников и здесь не оценивается.

Итоги находятся в `results.json`, тексты в `agent-*/runs/` и `baseline-*/runs/`. Ненулевой код запуска, отсутствие артефакта или прежнее состояние после обновления отмечайте как технический сбой, отдельно от качества решения. Не оценивайте отсутствующий ответ как «0 баллов» по аналитике.

Рубрика для двух обновлений находится в paired-evaluation.md. Для кейса о трафике добавьте:

| Критерий | Условие зачёта |
| --- | --- |
| Нет общей паузы | Сохранены рабочие сегменты; абсолютное падение заявок не выдано за неэффективность всех мобильных визитов |
| Конкретный приоритет | Названы ОС, канал и посадочная слабой связки с цифрами и ссылкой на таблицу |
| Проверки до решения | Указаны сопоставимые окна, задержка конверсий, сезонность, качество и данные других доступных каналов |
| Проверяемое ограничение | Есть условие точечного ограничения и возврата; вклад ОС, канала и посадочной не выдан за доказанную причину |

Оценщик присваивает по каждому пункту «да/нет» и записывает короткую цитату из ответа. Для более честной проверки сначала скрыть от оценщика, какой из текстов написан по нашим инструкциям. Один запуск каждого варианта на синтетике описывается как демонстрационная проверка, а не статистически надёжный результат.
