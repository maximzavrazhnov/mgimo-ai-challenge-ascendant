# История версии 0.6

В версии 0.6 появились кейс МегаФона, расчёт экономики, возобновление прогона и карточка выбора руководителя. [Актуальная инструкция запуска](../README.md). Ниже описаны команды для дополнительных проверок.

## Посмотреть демонстрацию

Откройте `evidence/preview.html` в браузере. В `docs/paired-run-results.md` приведены результаты, ограничения и время по этапам. В `docs/traffic-comparison.md` приведено отдельное сравнение с базовым Codex.

## Кейс МегаФона: запуск и продолжение

В [демонстрационном проекте](../demo/megafon/) собраны бриф, учебные вводные и результаты двух сеансов. [Исходная аналитическая записка](megafon-strategy-draft.md) показывает, как стратегия выглядела до прогонов.

Из корня репозитория:

```text
python tools/operator_model.py demo/megafon/assumptions.json
python tools/run_comparison.py eval-megafon --scenario megafon --arm agent --timeout 600
```

Для расчёта нужны только Python 3.10+ и файлы проекта. Для прогона нужен установленный Codex CLI, вход в аккаунт с доступной квотой и подключение к модели. Проект не требует отдельного ключа. Если нужен только входной пакет без модели, добавьте `--prepare-only`. Для отдельной проверки веб-доступа откройте `eval-megafon/inputs/megafon-eval` в агентной среде с веб-инструментом; попросите самостоятельно открыть только публичный источник из `demo/megafon/public-source.md`, назвать проверенный раздел и решение, на которое он повлиял. Штатное сравнение выполняется без веб-доступа агента; там используется заранее проверенная выдержка. При независимой проверке ограничьте входы брифом, допущениями и выбранным источником.

После сбоя запустите:

```text
python tools/run_comparison.py eval-megafon --resume --timeout 600
```

`progress.json` хранит попытки, `results.json` обновляется после этапа, прежние неполные рабочие папки сохраняются в `partial/`, журналы остаются в `logs/`. Проверенные завершённые этапы пропускаются; неполный этап повторяется со входа этапа. Не запускайте два процесса одновременно в одну папку. Решение и состояние ищите в `eval-megafon/agent-megafon/runs/`. Для отдельного сравнения используйте новую папку и `--scenario megafon --arm both`; через `--model` укажите известный идентификатор доступной модели, одинаковой для обеих версий.

### Карточка выбора руководителя

После решения человека запишите его вместе с ответственным, метрикой, датой пересмотра и условием остановки. Пример с условной датой:

```text
python tools/decision_card.py eval-megafon/agent-megafon show
python tools/decision_card.py eval-megafon/agent-megafon record --gate Q1 --choice observe --owner "Руководитель продукта" --rationale "Не подтвержден темп набора" --metric "Доля ограниченных индексных номеров за 7 дней" --review-on 2027-03-31 --stop-if "Доступ после отзыва согласия"
```

Карточка сохраняется в `runs/decision-card.json`. Если решение агента или его состояние изменится, статус будет `needs_review`. История карточек сохраняется; действий у оператора инструмент не выполняет.

## Сценарий анализа воронки

1. Откройте папку в агентной среде с терминалом и доступом к файлам. Для локальных расчётов нужен Python 3.10+; зависимости и API-ключи не нужны. Модель предоставляет сама среда. Для чтения открытых сайтов нужен её веб-инструмент; локальные расчёты работают без сети.
2. Напишите: «Прочитай AGENTS.md, workflow.md и demo/brief.md. Начни разбор воронки в фазе A, используя таблицы, историю и открытый источник из demo/source-register.md».
3. После первого решения попросите сохранить его в `runs/`. В новом чате: «Прочитай AGENTS.md и runs/state.json. Продолжи с сохранённого шага. Теперь добавь материал из demo/update и пересмотри выводы».

Для независимого прогона сначала запустите `python tools/prepare_eval.py eval-inputs` и откройте только созданную папку `eval-inputs/stage-a`. Папки `reference/` и `evidence/` используются после получения ответа. Фаза A не должна читать `demo/update/` и `demo/alternative-update/`: это два взаимоисключающих пакета новых материалов для одного исходного запроса. Чтобы сравнить сценарии, сделайте две копии состояния сразу после фазы A. Порядок проверки: `docs/paired-evaluation.md`.

Локальная проверка:

```text
python tools/funnel.py analyze demo/funnel.csv
python tools/funnel.py analyze demo/funnel.csv --update demo/update/definitions.json
python tools/funnel.py analyze demo/funnel.csv --update demo/alternative-update/definitions.json
python tools/funnel.py history demo/history.csv short-form
python tools/segments.py demo/traffic-review/traffic.csv
python tools/prepare_eval.py eval-inputs
python tools/run_comparison.py eval-traffic --scenario traffic
python -m unittest discover -s tests -v
```

На Windows подойдёт `py -3` вместо `python`, если так настроена система. Вспомогательные расчёты версии 0.6 проверялись в Linux. Сервис, таблицы, продуктовые документы и история экспериментов вымышлены.

Дополнительная проверка: откройте в отдельном новом чате только папку `eval-inputs/traffic-eval`, созданную `prepare_eval.py`. Запрос находится в брифе. Результат должен раздельно показать, что сохранит агент, что исследует и какая дополнительная информация оправдает паузу конкретной связки. После ответа сверяйте с `reference/traffic-review.md`; дословное совпадение не требуется.
